# 长表单渲染性能

[图文示例](EXAMPLES.md) · [原始数据](benchmarks/latest.json) · [测量脚本](https://github.com/eugeneaiao-ui/formino/blob/main/scripts/benchmark.mjs)

本报告测量真实 Chrome 中的生产构建。它描述当前版本在这台机器上的结果，不代表所有设备，也不与未测量的其他库比较。

## 指标与场景

- 普通长表单：100、300、1000 个 Ant Design Input，三列布局；每项均有 required 校验与初始值。
- 完整挂载与 progressive 分批挂载各测一组。每批 3 行 × 3 列 = 9 项。
- 联动场景：100 个 NumberInput，1 个源值驱动 99 个计算字段。更新计时会等到所有目标值正确。
- 首批 DOM：从 root.render 调用前，到 MutationObserver 首次观察到控件；不是首屏绘制指标。
- 全部 DOM：观察到全部控件的时间，保留在原始数据 allCommittedMs 中。
- 全部就绪：观察到全部控件，再等待两次 requestAnimationFrame；检查实际 DOM 数与表单注册数都等于配置数。
- 编辑稳定：从真实 input 事件开始，到值 / 所有计算目标更新正确并经过两帧；不包含浏览器自动化通信耗时，不等同于 INP。
- 校验：form.validateFields() Promise 完成的时间；所有数据有效，不包含错误提示重绘。

requestAnimationFrame 回调发生在重绘前，两帧是这里的稳定观察边界，不能视作精确像素绘制完成时间。参见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)。

## 本次实测解读

- 完整挂载的全部就绪中位数：100 字段 210.1 ms、300 字段 525.8 ms、1000 字段 1770.0 ms。
- 1000 字段分批模式首批为 256.6 ms，但全部就绪达到 28286.0 ms。当前默认每批 9 项时，全量完成成本很高，不能把首批时间当作整表性能。
- 1000 字段最终都是 9447 个 DOM 节点，分批没有减少最终 DOM。完整挂载后编辑稳定中位数 48.5 ms，全部有效字段校验中位数 439.3 ms。
- 100 字段 / 99 个直接计算目标的编辑稳定中位数为 168.9 ms。这是 NumberInput、表单通知和计算写入共同产生的成本，不是纯计算函数耗时。
- 当前版本保持 progressive=false 为默认值。需要尽快完整可用时优先评估完整挂载；非常大的业务表单还应考虑合理分组 / 分步，不能把当前分批模式理解为虚拟滚动。

以上解读对应本次记录。项目更名为 Formino、包名调整为 forminojs；历史测量数据与原始指纹保持不变，未因更名重新计时。以后复测更新原始数据时，请同时检查本段；数值不代表冷启动、移动设备或不同字段组合。

## 如何复现

```bash
npm ci
npm run benchmark
```

在源码仓库运行上述命令。默认使用系统 Chrome 的独立 headless 实例，不读取个人浏览器资料。没有 Chrome 时可先安装 Playwright Chromium，再使用对应选项：

```bash
npx playwright install chromium
BENCH_BROWSER=chromium npm run benchmark
```

Windows PowerShell 可先设置环境变量，再运行：

```powershell
$env:BENCH_BROWSER = 'chromium'
npm run benchmark
```

可用 BENCH_SAMPLES 调整正式次数。npm run benchmark:smoke 是单次检查，不更新正式性能报告。脚本会先构建生产页面，完成测量后再验证并截图四类示例；结果写入 docs/benchmarks/latest.json，报告中的结果表随之更新。

## 解释和使用边界

- JS / CSS 已加载的页面内，每次重新挂载一个新表单；首轮预热不纳入数据。排除冷启动下载、打包、模块解析、测试配置数据创建和真实 API 延迟，包含 useDynamicConfig 生成配置及控件挂载。
- benchmark 独立入口没有 React.StrictMode，避免开发模式重复执行干扰。采用实际生产 React / AntD，未限 CPU、未模拟网络；同机后台负载仍会影响结果。
- progressive 优先让首批可见，不承诺全部完成更快。完成后仍保留所有字段，不是虚拟滚动；大表单依然有完整 DOM 和表单状态开销。
- 提交和整表校验必须等所有字段注册完成。演示页也会在字段数未齐时禁用整表校验按钮。
- 输入类型、校验规则数量、联动图规模、自定义组件、异步接口和设备都会影响耗时。当前 Input 基线不能替代所有复杂业务表单的实际压测。
- 多级联动的交互正确性在截图脚本中单独验证；它不等同于这里的 99 项直接依赖压力样本。
